Agent Architecture

Components, data flow, tools, and decision-making logic

Two-Pass Architecture

Pass 1: Zeek Sweep

  • Covers all 9 days
  • Downloads only Zeek structured logs (11 datasets/day)
  • Runs 4 agents on lightweight parsed data
  • Flags suspicious days for drill-down
  • Fast — mostly I/O-bound (~30 min total)

Pass 2: PCAP Drill-Down

  • Only flagged days (typically 3–5 of 9)
  • Downloads 1 PCAP per day (1–5 GB each)
  • Full tshark-based deep analysis
  • File extraction & artifact inspection
  • Packet-level confirmation (~1–2 hrs/day)

Why two passes? Single-pass: 50+ GB disk, 12+ hours  →  Two-pass: 4.5 GB peak, ~6 hours

Drill-Down Decision (Rule-Based)

A day is flagged for PCAP if ANY:

  • Successful RDP session > 10 KB
  • Brute-force count > 1,000
  • Lateral movement detected
  • Exfiltration detected
  • Alert count > 50 on that day

Agent Step Limits

  • Payload (Zeek): 8 steps

Key Challenges

Technical challenges, false positives, tool limitations, scaling

Technical Challenges

ECS Field Mismatch

API returns Elastic Common Schema format (source.ip) but tools expect Zeek format (id.orig_h)

✓ ecs_compat.py auto-translates 40+ fields across 12 log types — transparent to all agents

Google Drive Quota

Public links hit per-file quota limits; downloads fail mid-pipeline

✓ "Quota latch" — first failure permanently switches to authenticated Drive API, saving ~30 min of retries

Large PCAP Analysis

1–5 GB PCAPs cause tshark queries to take 1–2 minutes each

✓ Pre-filter by port in display filters; PCAP-only on flagged days; 120–300s timeouts with fallback

Multi-Day Correlation

Attack spans 9 days; Patient Zero on Day 1 must influence Day 5 analysis

✓ Rolling attack context propagates chronologically; findings accumulate across days

False Positives & Detection Gaps

Area Challenge Mitigation
DNS Tunnelling C2 beaconing mimics tunnelling (high query rate + entropy) Conservative thresholds: entropy > 3.5 bits/char, label > 40 chars, rate > 200/5min; require multiple indicators
Exfil Volume Legitimate backup/sync generates large outbound volumes CDN/service port filtering; beaconing CV coefficient check
Lateral Movement Encrypted RDP/SMB hides operation details in Zeek logs Fall back to tshark packet inspection in Pass 2
Missing Data Not all 11 Zeek datasets available on every day Graceful degradation; provenance logs record gaps
LLM Hallucination LLM can invent IPs/domains not in evidence Post-generation grounding check; hallucination risk scoring

Tool Limitations & Scaling

Limitations

  • tshark timeouts — Complex queries on large PCAPs exceed 300s; simplified fallback queries used
  • LLM step exhaustion — 30-step IA ReAct loop may not cover all leads; forced best-effort report
  • Disk constraints — 5 GB soft limit; large Zeek datasets may temporarily exceed it
  • No encrypted payload inspection — Cannot analyse encrypted file transfers

Scaling Characteristics

  • Runtime scales linearly with days (~40 min/day Zeek sweep)
  • CPU-light — ~6% peak; network-bound (80% of time)
  • RAM-light — ~200 MB peak
  • Disk-managed — Sliding window keeps ≤4.5 GB
  • Checkpoint/resume — Crash-resilient; resumes from last completed day

9 days → ~6 hours
vs. 12+ hours single-pass

Guardrails & Safety Controls

Anti-hallucination, validation, constraints, human-in-the-loop

Anti-Hallucination: 5 Layers

1. Evidence-Only Prompts

"Never fabricate packet IDs, hashes, users, hosts, ATT&CK IDs, or timestamps"

"Write Insufficient evidence rather than guessing"

2. Low Temperature

All LLM calls use temperature = 0.0 – 0.1

Maximises determinism and factual output

3. Grounding Check

Post-generation verification:

  1. Extract IPs & domains from LLM output
  2. Extract entities from source evidence
  3. Verify every mention exists in evidence
  4. Score: 0.0 → 1.0 grounding

4. Structured Schemas

Agents return fixed JSON fields — no room for free-form hallucination. E.g.: {"summary", "deployment_method", "payload_files", "source_host", "target_hosts"}

5. Deterministic MITRE

ATT&CK technique matching uses keyword lookup against static database, not LLM inference. The LLM cannot fabricate technique IDs.

Agent Constraints & Validation

Constraints

  • Step limits — 8 to 30 steps per agent; prevents runaway loops and cost
  • Token budgets — Tool outputs capped at 12K–15K chars; report at 16K tokens
  • Deterministic routing — Fixed agent order eliminates orchestrator hallucination
  • Mandatory checklists — IA agent must address 8-point checklist before report submission

Validation Steps

  • IOC deduplication — merge_all_iocs() across all agents
  • RFC1918 verification — Compromised hosts must be internal IPs
  • MITRE threshold — Threat groups need ≥2 overlapping techniques
  • Magic number checks — Extracted files verified (PE, 7-Zip, ZIP)
  • Entropy threshold — Suspicious files > 7.0 entropy
  • Evidence citations — Every claim must reference data

Human-in-the-Loop Considerations

Interactive Mode

Terminal attached: prompt user to select PCAP when multiple candidates exist

User picks best PCAP per day, or accepts auto-selection

Non-Interactive

CI/CD or background: auto-selects best PCAP by alert score

Generous drill-down thresholds — errs on side of investigation

Debug Mode

--only lateral_movement

Run single agent for targeted investigation without full pipeline

Provenance Audit Trail

Full record of which files each agent accessed per day — enables post-hoc human review of the pipeline's evidence basis. Appended to every generated report.

Key Trade-offs

Speed vs. Coverage

Two-pass: Full 9-day coverage in 6 hrs
Single-pass: 12+ hrs, 50+ GB disk

Accuracy vs. Cost

Higher step limits → more thorough but more API calls. Current: balanced at 8–30 steps/agent.

Determinism vs. Flexibility

Fixed routing eliminates hallucination risk at supervisor level; LLM flexibility within each agent.
